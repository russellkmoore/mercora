<objective>
Resolve the empty `handlePaymentFailed` stub as telemetry, and only telemetry: map Stripe's decline
information through a closed allow-list, emit one registered `payment.intent_failed` event, and
leave order state completely untouched.

Purpose: OBS-05. `app/api/webhooks/stripe/route.ts:344-362` currently receives every failed payment
Stripe reports and does nothing with it. An operator has no signal at all. The requirement also
demands that no placeholder task marker remain in the file, and that the resolution be written down
for the Phase 3 runbook update.

Output: a new pure `decline-reason` mapper, a real `handlePaymentFailed` body, a new test file, and
a `deferred-items.md` hand-off note for RUN-02.
</objective>

    payload originates outside the trust boundary, and an `unknown` parameter forces the runtime
    guards above to exist rather than letting the type system imply a shape the wire cannot promise.

    directly with plain object literals.

| Webhook payload → commerce state | The boundary ADR-WRI draws: no order-state change outside the ledgers |
