  <action>
    Measure, do not yet write the document. Work entirely in a scratch directory: `WORK=$(mktemp -d)`.

    **Discover the URLs (D-14).** Fetch `https://voltique.russellkmoore.me/sitemap.xml` once with
    `curl -s`. Extract the first `<loc>` whose path begins with the category segment and the first
    whose path begins with the product segment, in document order. Record both full URLs and both
    slugs verbatim — the document must name them so the measurement is reproducible, and "first in
    the sitemap" is only meaningful if the reader can see which one that was. Those two, plus
    `https://voltique.russellkmoore.me/` and `https://voltique.russellkmoore.me/checkout`, are the
    four targets. Fetch the sitemap exactly once; do not crawl further.

    If the sitemap yields no category URL or no product URL, do not substitute a guess and do not
    drop the row. Record the empty discovery and the reason, and carry that fact into Task 2.

    Before measuring, check each of the four URLs with a single `curl -sI -o /dev/null -w '%{http_code} %{redirect_url}'`
    and record the status and any redirect target. This is where the checkout question gets answered
    concretely rather than inferred from the score: note whether `/checkout` serves a page or
    redirects, and if it redirects, note where to. If two of the four resolve to the same final URL,
    record the collision — Task 2 still shows four rows.

    **Measure (D-13, D-16).** For each of the four URLs, run Lighthouse three times:

    ```
    npx --yes lighthouse@13.4.1 "<url>" \
      --form-factor=mobile --screenEmulation.mobile \
      --only-categories=performance \
      --output=json --output-path="$WORK/<slug>-<run>.json" \
      --chrome-flags="--headless=new --no-sandbox" \
      --quiet
    ```

    Pin the major version rather than taking whatever `npx lighthouse` resolves to that day, so the
    document's version line matches what actually ran. Keep the default mobile throttling — do not
    pass a throttling override; the PRD target of 85 is a mobile-emulation number and changing the
    throttle would make the comparison meaningless. If Chrome is not auto-discovered, set
    `CHROME_PATH` to the installed binary and retry; do not switch to a remote or hosted runner.

    Twelve runs total. Do not exceed three per route (D-16) and do not measure a fifth URL.

    **Extract (D-16).** For each route, read the three JSON files and pull four numbers per run:
    `categories.performance.score` multiplied by 100 and rounded to an integer,
    `audits['largest-contentful-paint'].numericValue` rounded to whole milliseconds,
    `audits['cumulative-layout-shift'].numericValue` to three decimal places, and
    `audits['total-blocking-time'].numericValue` rounded to whole milliseconds. Take the **median**
    of each metric independently: sort that metric's three values ascending and take the middle one.
    Never a mean, never the best run. Record all twelve raw triples in the scratch directory so
    Task 2 can show the spread if a route's runs disagree sharply.

    Also capture, from the first JSON file, `lighthouseVersion` and the Chrome version reported in
    `environment.hostUserAgent`. Task 2 records both.

    Leave every JSON file in the scratch directory. Nothing from `$WORK` is copied into the
    repository (D-15).
