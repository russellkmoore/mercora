## Shell rules for every command in this plan

Confirmed live in `04-RESEARCH.md` "Common Pitfalls" #2: a shell hook intercepts bare `grep` and `find` in this environment and returns wrong counts (a bare `grep -n ... | wc -l` returned 59 where the correct answer is 19).

- Use absolute paths in every gate: `/usr/bin/grep`, `/usr/bin/sed`, `/usr/bin/find`, `/usr/bin/wc`, `/bin/ls`, `/usr/bin/basename`, `/usr/bin/cut`.
- Never use `diff <(...) <(...)` — a shell function shadows `diff`.
- Never run `npx vitest` inside a `bash -c` string — use `./node_modules/.bin/vitest run`.
- `/usr/bin/grep -c` on a file with no match prints `0` and exits 1. Inside `"$( ... )"` the exit code does not reach `test`, so `test "$(...)" = "0"` is the correct clean-file idiom. Do not add `|| echo 0` fallbacks — they convert a wrong path into a passing gate.
