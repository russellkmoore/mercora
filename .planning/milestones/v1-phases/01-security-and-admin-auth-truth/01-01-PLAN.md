<objective>
Build the deployment posture guard end to end and prove, with a runnable test, that a
deployed Worker running a development build cannot open the admin bypass.

Purpose: `lib/auth/admin-middleware.ts:22` and `lib/auth/unified-auth.ts:163` both open
privileged paths purely on `process.env.NODE_ENV === "development"`. Nothing today prevents
a development build from reaching production. SEC-03 closes that.

telemetry event wired into the alert escalation list, the guard called from
`checkAdminPermissions`, and unit tests that fail if any of it regresses.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Unauthenticated internet → `app/api/**` route handlers | Attacker-controlled headers, including `x-dev-admin`, `Authorization`, and `X-API-Key`, cross here |
| Build-time configuration → runtime auth decision | `process.env.NODE_ENV` is baked at build time and consumed as an authorization input |
