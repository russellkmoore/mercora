Finish the deployment posture guard: wire it into the second auth choke point and into
`middleware.ts` so admin routes return a real HTTP 503 on the wire, then write the operator
documentation for it.

admin under `NODE_ENV === "development"`, and `middleware.ts:82-86` returns
`NextResponse.next()` unconditionally for every admin path, so nothing at the edge would stop
a misbuilt deploy.

and the two documentation entries D-SEC-04 requires.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Unauthenticated internet → Next.js middleware | Every request, including admin paths, crosses here before Clerk runs |
| Unauthenticated internet → `authenticateRequest` service-token and Clerk-session paths | Attacker-controlled `Authorization` / `X-API-Key` headers and session cookies cross here |
| Build-time configuration → runtime authorization decision | `NODE_ENV` baked at build time is consumed as an authorization input |
