## Planner Assumptions

1. **The production apply is a data write, not a migration.** `docs/database-migrations.md` states the migration runner does not seed or erase data, and `products.type` and `fulfillment_type` already exist. ADR-DBM's production gate and `MERCORA_ALLOW_PRODUCTION_MIGRATIONS` are therefore not in play, and `npm run deploy` and `npm run deploy:ci` are not involved (D-13).
2. **No redeploy is needed for the product to appear.** `app/product/[slug]/page.tsx` sets `revalidate` to 0, so the live Worker reads D1 fresh on every request. The category page has no such export, so `/category/featured` may serve from the incremental cache for a while — that is why the Featured-position truth is a backstop rather than a gate.
3. **The apply is reversible but costly.** Undoing it means hand-running deletes against production D1 for five rows. That is why a decision checkpoint sits in front of it and this plan is not autonomous, even though the individual commands run in the executor's own shell under Russell's existing wrangler login.
4. **Between this phase and Phase 10 the live product is buyable but not checkout-completable.** A shopper who adds it to the cart is refused by the existing pricing guard, which requires a recipient customization on a gift-card line. D-12 accepts this as a demo-site interim and notes that flipping the seeded status to draft is a one-word change if Russell would rather it were hidden.
