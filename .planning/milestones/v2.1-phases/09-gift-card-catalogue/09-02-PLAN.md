## Planner Assumptions

1. **The mixed-order test injects a fake D1 rather than mocking a module.** `stageInventoryAdjustments` takes an optional `database` in its options bag and `resolveDatabase` returns it unchanged when supplied, so a hand-written object with `prepare` and `batch` is enough. This is preferred over `vi.mock` because it exercises the real code path.
2. **The gift-card-only case needs no fake at all.** `stagePaidInventoryAdjustments` builds its input list from `aggregateOrderDemand`, and `stageInventoryAdjustments` returns immediately on an empty list before any database resolution. A gift-card-only order therefore resolves without ever touching D1 — which is itself the proof that the line was skipped.
3. **`available_for_sale` is derived, never stored.** There is no column to seed and no fixture field to set; the assertion is on the output of `toPublicProduct`.
