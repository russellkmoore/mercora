# Phase 11 Plan 01: Local Gift-Card Key-Ring Proof Summary

**Proved the exact production key-ring pipeline shape locally against the real frozen parsers, before any production secret exists.**

## Performance

- 2 tasks, 1 commit, 1 file changed (54 insertions), ~8 minutes.
- `actuals.tokens` (chars/4 over the realized diff) came in far under the 30000-token estimate — the plan's own estimate priced in reading a wide `read_first` set across both tasks, not the size of the eventual diff, which was a single test file extension.

## Accomplishments

- **Task 1:** Generated `.dev.vars` — an untracked local development key ring — with the exact non-materializing shell pipeline plan 11-04 will run against production. Proved `git check-ignore -v .dev.vars` resolves to `.gitignore:44:.dev.vars*` *before* the file existed, then appended four `GIFT_CARD_*` lines (HMAC ring version+keys, delivery ring version+keys) using a brace-group of `printf` calls whose only source of randomness was `$(openssl rand -base64 32)` interpolated directly into the `printf` format string — never assigned to a variable, never echoed, never read back. Verified afterward using only line-count and name-prefix assertions (`sort -u | wc -l` = 4) and `git status --porcelain -- .dev.vars` (empty).
- **Task 2:** Extended the existing `describe("gift-card runtime configuration", ...)` block in `tests/unit/lib/gift-cards/config.test.ts` with five new cases, all built from in-memory fixtures (`btoa("0".repeat(N))` over repeated ASCII characters — no long opaque literal that reads like a real key):
  - Accepts an HMAC key shaped like `openssl rand -base64 32` output (44 UTF-8 bytes, well over the 32-byte floor).
  - Rejects an HMAC key one byte under the floor (31-character ASCII string).
  - Accepts a delivery key of canonical base64 decoding to exactly 32 bytes (`base64:` + `btoa("0".repeat(32))`).
  - Rejects a delivery key that decodes to 31 bytes — the boundary case one byte under AES-256, distinct from the existing 16-byte rejection case.
  - Rejects a delivery key with no `base64:` prefix, even though the bare payload decodes to the right length.

## Issues Encountered

- The local shell (`zsh` with `NO_CLOBBER` on) blocks both `>` on an existing file and `>>` on a *non-existing* file with a "no such file or directory" error — a zsh-specific `NO_CLOBBER` behavior (it also guards append-create, not just overwrite). Worked around with the shell's own force-append operator (`>>!`) for the one-time `.dev.vars` creation, and force-write (`>!`) for a scratch verification tmp file. No value was echoed or displayed at any point during this workaround; only the pipeline's target changed from `>>` to `>>!`.
