<objective>
Sweep the CMS page blocks and the blog surfaces to the token contract.

Purpose: TOKEN-03 covers every storefront template, not only the routes on the screenshot grid.
The CMS block components are the highest-risk omission in the phase — a merchant-authored page
composes them at runtime, so an untokenised block would render a raw palette value on a page
nobody screenshotted. Sweeping them is what makes "no storefront component or template holds a
hardcoded palette value" a true statement rather than a route-shaped one.

Output: twelve content files scan-clean, with a screenshot set covering the blog index, a blog
post, and one CMS page — three cells outside the standard D-20 grid, added because these
surfaces would otherwise ship with no visual evidence.
</objective>
