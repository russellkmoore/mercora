and deliberately loads no stylesheet, no provider, and no router component — it is the fallback
when the root layout itself fails. Its seven colours live in inline `style` objects, which is
why it needs `getThemeTokens()` rather than class names. Its background today matches the
elevated-surface token value, its body text matches foreground, its muted paragraph matches
muted-foreground, its button background is a hover-darkened orange that snaps to primary (S11),
and its outline-button border is a mid neutral that snaps to the border token.

Because this page renders with no provider, it must import `getThemeTokens()` directly rather
than using the `useThemeTokens()` hook plan 05-10 added — the hook throws outside the provider,
and this page is by definition outside it.

`app/layout.tsx` today passes Clerk only `{ theme: dark }`. D-12 keeps that base theme and adds
a `variables` block sourced from `getThemeTokens()`. The layout already calls `getThemeTokens()`
as of plan 05-10, so reuse that call rather than adding a second one.

`app/order-status/[id]/page.tsx` contains `text-text-secondary`, a class that resolves to
nothing in this codebase. D-17 maps it to the muted-foreground token.
