<interfaces>
<!-- Contracts the executor needs. Do not go looking for these in the codebase. -->

Script convention (`scripts/build-with-public-env.mjs`): `#!/usr/bin/env node` shebang, ESM
imports, flags read positionally off `process.argv.slice(2)` by locating the flag then taking
the next element, a usage line plus `process.exit(1)` when required flags are absent, and all
work wrapped in a try/catch that prints `[<tag>] ABORT: ${error.message}` before exiting 1.
This plan's tag is `screenshot-routes`.

`app/sitemap.ts` emits absolute URLs for `/`, `/blog`, every `/product/<slug>`, every
`/category/<slug>`, every CMS `/<slug>`, and every `/blog/<slug>`, capped at 50k entries.
It is served at `/sitemap.xml` and is `force-dynamic`, so it reflects whatever the local D1
seed contains.

Local development data comes from `mise exec -- npm run dev`, whose `predev` hook runs
`scripts/db-local-ensure.mjs` — this applies local D1 migrations and then `data/d1/seed-dev.sql`.
The seed provides products and categories. It does not necessarily provide an order, which is
why `/order-status/<id>` is an explicitly-handled MISSING case rather than an assumed route.

Playwright API surface used: `chromium.launch()`, `browser.newContext({ viewport })`,
`page.goto(url, { waitUntil })`, `page.click(selector)`, `page.screenshot({ path, fullPage })`.
</interfaces>

  <action>
    Install `playwright` and `@playwright/test` as devDependencies with `mise exec -- npm install -D`,
    then run `mise exec -- npx playwright install --with-deps chromium`. Pin nothing beyond what
    npm resolves; record the resolved version in the summary.

    Add the screenshot output directory to `.gitignore` as a root-anchored entry so the captured
    PNGs are never committed (D-19). Add `"screenshot:routes": "node scripts/screenshot-routes.mjs"`
    to `package.json` scripts, alongside the `scan:tokens` entry from 05-01.

    Create `scripts/screenshot-routes.mjs` using the flag-parsing and ABORT convention named in
    `<interfaces>`, with the tag `screenshot-routes`, importing `chromium` from `playwright`.

    Flags: `--base-url <url>` defaulting to `http://localhost:3000`; `--label <name>` naming the
    capture set and thus its output subdirectory; `--order-id <id>` supplying the order-status
    route's identifier; `--allow-missing` downgrading an unresolvable route from a hard failure
    to a recorded row; `--allow-remote` required before any non-localhost base URL is accepted;
    `--manifest <path>` naming the markdown file to append the coverage table to.

    Refuse a base URL whose hostname is neither `localhost` nor `127.0.0.1` unless `--allow-remote`
    is present, and ABORT with a message naming the privacy reason. The account, checkout, and
    order-status routes render real customer names, addresses, and order contents; the harness must
    make pointing it at a live store a deliberate act, not a default.

    Resolve dynamic slugs by fetching `/sitemap.xml` from the base URL and taking the first
    product URL and the first category URL it contains. If either is absent, that route becomes
    a MISSING row.

    Build the coverage grid from `05-TOKEN-MAP.md` §8: seven route cells (home, category, product,
    cart, checkout, account, order-status), each captured at viewport 1280x900 and 390x844, each
    at a resting state and one open interactive state. The cart cell is the home route with the
    cart drawer opened — there is no standalone cart route in this app. Use the interactive state
    named in §8 for each remaining cell.

    Name every output file deterministically as `<label>/<route>__<viewport>__<state>.png` using
    only the route key, the viewport width, and the state name — never a timestamp, a counter, or
    an index. Determinism is what makes a before/after pair align by filename alone. De-duplicate
    the grid by resolved URL plus viewport plus state before capturing, so two cells that resolve
    to the same page produce one file and one manifest row rather than two writes racing for one
    name.

    After each capture, compute the SHA-256 of the PNG bytes and carry it into the manifest row.

    Append to the manifest file a section for this label containing one table row per coverage
    cell with route, viewport, state, file path, and content hash; a MISSING row for every cell
    whose prerequisites could not be resolved, stating which prerequisite was absent; and an
    empty intentional-snaps subsection for the caller to fill.

    Exit 1 when any cell is MISSING unless `--allow-missing` was passed; exit 0 with a
    `[screenshot-routes] captured N cell(s), M missing` summary line otherwise.
  </action>
