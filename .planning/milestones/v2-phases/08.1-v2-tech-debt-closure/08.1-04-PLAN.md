<objective>
Close the one email path Plan 02 could not: order-confirmation and merchant-notification effects
drained from the every-five-minutes recovery sweep. That sweep runs in a Cloudflare `scheduled()`
handler with no request-scoped context, so resolving the theme there silently yields the default
(RESEARCH Pitfall 1). Per D-10 the theme is resolved when the effect is *staged* — inside the
request that creates it — and carried on the row.

Purpose: makes D-01 true for every send path, not just the request-scoped ones.
Output: one expand-only migration, a theme on the staged effect payload, a drain that honours it,
and integration coverage proving both the honoured case and the pre-existing-row fallback.
</objective>
