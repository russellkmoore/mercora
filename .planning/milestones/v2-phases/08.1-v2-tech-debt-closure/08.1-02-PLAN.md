<objective>
Make every transactional email follow the admin-selected theme (D-01). The pure, synchronous HTML
generators stop resolving a theme and take `tokens` as a parameter; the async senders — which
already run in a server context with database access — resolve the active theme once per send
through a small shared helper.

Purpose: closes the v2 audit's "emails always render the manifest default" debt for every
request-scoped send path. The one remaining path (the cron recovery drain) is Plan 04's job.
Output: a shared email-theme helper, six theme-aware builder files, and test coverage proving a
non-default theme reaches the rendered HTML.
</objective>
