### IN-01: `select.tsx` focus-highlight tint is visually subtle on some themes

**File:** `components/ui/select.tsx:119`
**Issue:** Computed `primary` @ 10% opacity over each theme's `surface-elevated` gives an RGB-distance of roughly 20-36 (out of a 441 max) across the seven shipped themes — visible but modest, smallest on `luxe` (~20). Not incorrect, and text contrast stays high (>11:1) in every case, but a designer reviewing pixel-level polish may want a slightly stronger tint (e.g., `/15` or `/20`) for consistency with `CategoryDisplay`'s referenced `hover:bg-primary/20` precedent, which this fix's own comment cites as the model but uses half the opacity.
**Fix:** Consider bumping to `focus:bg-primary/15` or `/20` if a design pass confirms the current value reads as too subtle on light-warm themes (atelier, luxe).

### IN-02: `SelectTrigger` in `ProductDisplay.tsx` has a no-op hover state

**File:** `app/product/[slug]/ProductDisplay.tsx:262`
**Issue:** `className="w-full border border-border bg-surface-elevated text-foreground hover:bg-surface-elevated sm:w-auto"` — `hover:bg-surface-elevated` is identical to the trigger's own resting `bg-surface-elevated`, so the hover class has no visible effect. Minor, pre-existing, not part of this phase's diff, but adjacent to the more serious `focus:` override that WR-01 fixed on the same component.
**Fix:** Remove the redundant `hover:bg-surface-elevated`, or replace it with an actual hover treatment if one was intended.
