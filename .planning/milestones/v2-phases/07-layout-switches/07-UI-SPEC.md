# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase has **two distinct UI surfaces** governed by different rules:

1. **Eight storefront variant components** (`components/layout/category/*`, `components/layout/home/*`, `components/layout/product/*`) — written in **token classes only** (frozen 23-token contract, `scan:tokens` stays 0; D-09), consumed under whichever theme preset is active. One flagged, deliberate exception exists for the full-bleed hero scrim — see `## Storefront Variant Anatomy § HomeHeroFullBleed`.
2. **A new "Layout" section on the existing Admin Appearance page** (`app/admin/settings/appearance/page.tsx` + new `components/admin/LayoutSwitches.tsx`) — a normal admin UI screen using admin's existing **hardcoded** neutral-800/900/950 palette (D-16 carried from Phase 5/6; TOKEN contract §Out of Scope: "Admin dashboard theming"). The `## Color` / `## Typography` sections below specify this surface directly; the storefront surface is specified via tokens, never hex, in `## Storefront Variant Anatomy`.

Both surfaces are additive to Phase 6's admin Appearance page and its `ThemePresetGrid` — nothing in that component or its file is modified (D-12).

## Color

**Storefront variants** (frozen 23-token contract, values vary by active theme — never hex in component code):

| Role | Token(s) | Usage |
|------|----------|-------|
| Dominant (60%) | `surface` / `surface-elevated` | Page/section backgrounds; `CategoryList` row fill and `ProductGalleryTop`'s image-placeholder background (both reuse `bg-surface-elevated`/`bg-border` exactly as `ProductCard` already does) |
| Secondary (30%) | `border`, `muted-foreground` | Thumbnail borders, list-row dividers (if any), description/caption text, unselected thumbnail ring |
| Accent (10%) | `primary` / `on-primary` | CTA buttons and pills, sale-price text, selected thumbnail border (`border-primary`, reused unchanged), List row's "Learn more →" CTA |
| Destructive/status | `success` (in stock), `warning` (coming soon) | Unchanged existing availability copy/tokens, reused verbatim in every category variant; not newly introduced |

Accent reserved for: CTA buttons/links, sale-price emphasis, and the selected-thumbnail border — identical to the roles `primary`/`on-primary` already carry today in `ProductCard`/`ProductDisplay`. No new accent usage is introduced.

**Flagged exception — `HomeHeroFullBleed` scrim (D-07):** the scrim over the hero photo and the two text lines overlaid on it use **literal, theme-independent colors** (`bg-black/50`, `text-white`, `text-white/80`), not tokens. Rationale: neither the main token set nor the inverse token set guarantees a dark backdrop across every theme polarity (Phase 6 already proved a token-relative `bg-surface/NN` scrim reads as a *light* backdrop under a light preset — the exact defect the light-preset QA pass caught for Dialog/AlertDialog/Sheet). A photo-behind-text hero needs a scrim that reads dark *regardless of theme*, which only a literal color can guarantee. Per the same precedent Phase 6 used to resolve that finding ("fixed to literal dark-alpha via the scanner's sentinel"), `components/layout/home/HomeHeroFullBleed.tsx` must be added to `scripts/scan-hardcoded-colors.mjs`'s `MANUAL_REVIEW` array with a written reason (e.g. "a photo-behind-text hero scrim must stay legible across every theme's polarity; no token pair guarantees a dark backdrop on both light and dark presets — see 07-UI-SPEC.md"). This keeps `scan:tokens` at 0 violations while printing the exception on every run, matching Phase 5's own precedent ("0 violations, 2 manual-review rows"). The CTA **button** inside the same overlay stays fully token-driven (`bg-primary text-on-primary`) — only the scrim and its two text lines need the exception, because the button's own contrast is already guaranteed by the token contract itself.

**Admin Layout section** (hardcoded, scan-excluded per D-16 — matches Phase 6's admin table exactly, reused verbatim):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` (`bg-neutral-950`) | Page background (unchanged, `app/admin/layout.tsx`) |
| Secondary (30%) | `#262626` (`bg-neutral-800`) / `#404040` border (`border-neutral-700`) | Option-button unselected fill/border |
| Accent (10%) | `#ea580c` (`bg-orange-600`, hover `#c2410c bg-orange-700`) | Save Layout button; selected option's fill/ring (`ring-2 ring-orange-500`, matching `ThemePresetGrid`'s pending-selection treatment) |
| Destructive | Not used | No destructive action exists — layout selection is reversible (select → Save → toast), same posture as Phase 6's theme selection |

Accent reserved for: the Save Layout button and each segmented group's selected-option indicator — nowhere else on this page.

### Admin Layout section anatomy (D-10/D-11/D-12)

Route: existing `app/admin/settings/appearance/page.tsx`, unchanged apart from appending the new section below `<ThemePresetGrid />` (and an optional `<Separator />` between them).

Structure, in order:
1. `<h2>` "Layout" (18px semibold) + subtitle paragraph (see Copywriting Contract), matching the page's existing `<h1>`/subtitle spacing pattern (`mb-2` heading, then paragraph).
2. Three segmented groups, each: `<div role="radiogroup" aria-label="{Group label}">` containing a `<h3>`-or-`<label>` group heading (14px semibold) above a `flex flex-wrap gap-2` row of option buttons. Each option button is a `Card` (or plain button styled identically) with `role="radio" aria-checked` following `ThemePresetGrid`'s exact roving-tabindex/keyboard pattern (arrow keys move within that group only; Space/Enter selects). Anatomy per option: 20px lucide icon (`w-5 h-5`) stacked or inline before a 14px label, `gap-2`, `px-4 py-2`, unselected = `bg-neutral-800 border-neutral-700 text-gray-300`, selected = `bg-orange-600/10 border-orange-500 ring-2 ring-orange-500 text-white font-semibold` (mirrors `ThemePresetGrid`'s pending-selection ring).
3. A single **Save Layout** button below all three groups (same disabled-until-dirty / "Saving…" spinner / toast pattern as `ThemePresetGrid`'s Save Changes), saving all three keys together in one `POST /api/admin/settings` call (D-12).
