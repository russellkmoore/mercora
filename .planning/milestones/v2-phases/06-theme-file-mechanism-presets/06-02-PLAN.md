<objective>
Make the theme the storefront renders a per-request decision rather than a hardcoded string: resolve
it from D1, fall back through the environment default to the manifest default, stamp it on the html
element blocking in the root layout, and emit a telemetry signal when a stored name no longer exists.

Purpose: THEME-02. Plan 06-01 proved a theme file reaches the browser; this plan makes *which* theme
reaches the browser a value an admin can change without a deploy. It also loads the Luxe display
face here, once, so that no theme file ever needs a font-loading at-rule (D-02).

Output: `lib/themes/active-theme.ts`, a registered `theme.unknown_selection` event, an async root
layout, and the wrangler var declaration.
</objective>

Create `lib/themes/active-theme.ts` exporting the two setting constants named in the interfaces block
and an async resolver, using the research skeleton as the literal starting point.

The resolver builds a set of manifest names, reads the appearance settings category through the
existing settings helper, and takes the stored value for the theme key. It trims a string value and
compares it case-sensitively against the manifest name set. On a match it returns that name. On a
present-but-unmatched value it emits the unknown-selection telemetry event and falls through. On an
absent, empty or whitespace-only value it falls through silently - an absent row is the expected
first-load state, not an anomaly, and the event's sample rate of 1 would make that noisy and
semantically wrong.

Fall-through resolves the environment default (read through `process.env` inside the function body,
never at module scope) if it is itself a manifest name, otherwise the manifest default constant.

Wrap the settings read in a try/catch that falls through on failure. This function runs in the root
layout on every request; a database hiccup must degrade to the default theme, not take down every
route.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| D1 `admin_settings` -> server render | The generic settings endpoint accepts any key/value pair, so the stored theme name is untrusted input by the time the layout reads it. |
| server render -> browser | The resolved name is written into an HTML attribute and the resolved token values are serialised into the client provider payload. |
| resolver -> telemetry / logs | A rejected stored value could be reflected into a log line consumed by the tail Worker and by operator alert email. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-05 | Tampering | `getActiveTheme()` reading `appearance.theme` from D1 | high | mitigate | Task 1 membership-checks the stored value against the generated manifest's names and falls back on any miss, so the value written into the html attribute is always a manifest key. This is the authoritative read-time control; the admin UI's own check in plan 06-04 is defence in depth, not the gate. Proven by the unknown-value and non-string behavior rows. |
| T-06-06 | Information Disclosure | the unknown-selection telemetry envelope | medium | mitigate | Task 1 emits only an allowed enum field describing the outcome; the stored string is never passed. The existing field sanitiser drops unknown keys, so even a future careless call site cannot leak it. Asserted by the "no telemetry argument contains the stored string" criterion. |
| T-06-07 | Denial of Service | a D1 failure inside the root layout | medium | mitigate | The settings read is wrapped so a rejection degrades to the environment or manifest default rather than failing every route in the app. Covered by the settings-read-rejects behavior row. |
| T-06-08 | Tampering | the resolved name reaching the CSS cascade | medium | mitigate | Because the resolved value is always a manifest key, and manifest keys are validated at build time as lowercase alphanumerics and hyphens (plan 06-01 rule 4), the attribute value can never carry quote or angle-bracket characters, so it cannot break out of the attribute regardless of what was stored. |
| T-06-SC | Tampering | npm / pip / cargo installs | low | accept | No package-manager install task exists in this plan. Cormorant Garamond ships inside the already-pinned framework's font package; `06-RESEARCH.md` section "Package Legitimacy Audit" records zero packages added this phase. |
