  <behavior>
    - Existing binding, Stripe agrees: `findPaymentCustomer` returns a row, `stripe.customers.retrieve` returns a customer whose `metadata.mercora_customer_id` equals the caller's customer id → returns the stored Stripe customer id and never calls `customers.create`.
    - Existing binding, Stripe disagrees: the retrieved customer's `metadata.mercora_customer_id` is a different shopper, or the customer is deleted → throws `PaymentCustomerConflictError`, binds nothing.
    - No binding: calls `customers.create` exactly once with `metadata: { mercora_customer_id }` and a deterministic idempotency key, binds the result, returns the new Stripe customer id.
    - Bind races and loses (`"conflict"`): re-reads the winner, verifies the winner against Stripe the same way, returns the winner's id — not the id this call just created.
    - Bind returns `"identical"`: returns that id without error (a benign double-bind of the same pair).
    - `findStripeCustomerId` returns `undefined`, not a thrown error, for a shopper with no binding.
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application → D1 | The only writer of `payment_customers`; a malformed provider id here would poison every later Stripe call |
| application → Stripe API | Server-side, secret-key calls; the shopper never participates |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-01 | Tampering | `payment_customers.stripe_customer_id` | high | mitigate | Table-level `CHECK (length BETWEEN 5 AND 255 AND GLOB 'cus_*')` refuses a non-Stripe-customer binding at the database, not in application code (D-01) |
| T-17-02 | Elevation of Privilege | `ensureStripeCustomer` conflict path | critical | mitigate | The winner of a bind race is re-read and re-verified against Stripe's own `metadata.mercora_customer_id` before it is returned; a mismatch throws `PaymentCustomerConflictError` instead of returning another shopper's customer (D-03) |
| T-17-03 | Tampering | `customers.create` retry | medium | mitigate | Deterministic `stableId("payment-customer", customerId)` idempotency key: a retried request reuses the same Stripe Customer rather than minting a second one (D-03) |
| T-17-04 | Information Disclosure | module log/error output | high | mitigate | No card data, Stripe secret key, or client secret is ever placed in a log line or an error message from this module |
| T-17-05 | Repudiation | orphaned binding after customer delete | low | mitigate | `REFERENCES customers(id) ON DELETE RESTRICT` refuses the delete while a binding exists, proven by an integration assertion (D-01) |
| T-17-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed by this plan; `stripe`, `@stripe/stripe-js` and `@stripe/react-stripe-js` are already installed, already in production use, and audited OK in 17-RESEARCH.md's Package Legitimacy Audit |
</threat_model>
