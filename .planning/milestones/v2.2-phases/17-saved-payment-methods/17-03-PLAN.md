## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server JSON → browser state | The Customer Session client secret lands in React state and is handed to Stripe.js |
| browser → Stripe Elements iframe | Card data is entered here and never crosses back into this app's JavaScript |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-12 | Information Disclosure | `CheckoutClient` state | high | mitigate | The Customer Session secret is only ever passed to `StripeProvider`; it is never logged, never written to `savePendingCheckout`, and never placed in a URL or a DOM attribute this app renders |
| T-17-13 | Information Disclosure | stale secret across a re-quote | medium | mitigate | The setter is called unconditionally in the response branch with a `?? ''` fallback, so a re-quote that returns no Customer Session clears the previous one instead of reusing it against a different PaymentIntent |
| T-17-14 | Information Disclosure | guest session | high | mitigate | A guest response has no such field, the state stays empty string, and the prop is passed as `undefined`, so the Elements options key is absent for guests (D-07) |
| T-17-15 | Spoofing | Stripe Link | low | accept | Link stays `'never'`; a shopper cannot be steered into saving a card to a third-party wallet the store does not control (D-12) |
| T-17-16 | Information Disclosure | card data in app JavaScript | critical | accept | Card entry stays inside Stripe's cross-origin iframe; no code in this plan reads, stores or transmits a card number (D-14) |
| T-17-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed by this plan; all three Stripe packages are already installed and audited OK in 17-RESEARCH.md's Package Legitimacy Audit |
