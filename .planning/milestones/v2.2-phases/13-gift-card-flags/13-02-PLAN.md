<objective>
Hide the gift-card product from every public browse surface when selling is off, without hiding
it from the admin product manager.

The trap this plan exists to avoid is documented in 13-RESEARCH.md Pitfall 1: `listProducts`,
`searchProducts` and `getProductsByCategory` are shared by the storefront and by
`/admin/products`. Filtering inside them would make the gift card unmanageable in phase 14. So
the filter goes at each public call site, through the one predicate built in plan 13-01 (D-14).

Purpose: satisfy the listing half of GCF-01 and GCF-03 without breaking admin.
Output: nine call sites filtered, a route test proving the admin/public split, and a
source-contract test that stops a future edit from sliding the filter into the model layer.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous request → `/api/products` | The same handler serves admin and public; a filter on the wrong side leaks or hides the wrong thing |
| Agent (Volt/MCP) request → catalog projection | An untrusted agent must see the same catalogue an anonymous browser sees |
| CMS editorial content → storefront render | Admin-authored slug references bypass the browse path |
