export type AddressFormState = {

- Export `AddressFormState` with the nine keys listed in `<read_first>`, taken verbatim from `AddressManager`'s current module-private `FormState` (line 6).

- Export `async function saveAddress(form, addressId?)`. It issues the same request `AddressManager.save()` issues today (lines 37–41) — the same two URLs, the same method selection (`PUT` when an id is supplied, `POST` otherwise), the same `content-type: application/json` header and the same JSON-stringified form body — and adds `credentials: "same-origin"` per D-02. It reads the JSON body as `{ address?: MACHCustomerAddress; error?: string }`, and when the response is not ok or carries no address it throws `new Error(body.error || "Address could not be saved")`. On success it returns `{ address }`. It must not persist any field value and must not write any field value to the browser console (D-07).

`components/account/AddressForm.tsx` (new, `"use client"`), props exactly as published in `<read_first>`:

Do not restyle and do not add or drop a field.
- Additionally give every control a `name` attribute equal to its state key — the nine keys are `label`, `type`, `line1`, `line2`, `city`, `region`, `postal_code`, `country`, `is_default`. This is inert for behaviour (the form stays fully controlled) and is what the Task 3 source contract greps for.
- When `props.lockType` is set, the type `<select>` is not rendered and the state's `type` stays pinned to `lockType`; when it is absent, the select renders exactly as it does today (Claude's discretion, CONTEXT recommendation).

- On submit it prevents the default, sets busy, clears the message, awaits `saveAddress(form, props.addressId)`, and on success calls `props.onSaved(address)`, resets its own state to `emptyAddressForm` merged with any `lockType`, and shows a polite success message. On a thrown error it shows that error's message as an assertive message and leaves the entered values in place so the shopper can correct them.
- The message is a single `<p>` rendered with `role="alert"` and `className="text-sm text-danger"` when it came from a failure, and with `role="status"` and `className="text-sm text-muted-foreground"` when it came from a success (D-01). Track which by holding the message as `{ kind: "error" | "success"; text: string } | null`.
- The outer `<form>` carries layout spacing only (`space-y-4`); the bordered card chrome stays in the consumer, so plan 15-02 can drop the same form into a dialog without stripping a border.
- The component must not persist any field value and must not write any field value to the browser console (D-07). It must not issue a network request of its own — every write goes through `saveAddress`.
