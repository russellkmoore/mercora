<objective>
Close DEBT-04. `deliverOne` emits the critical, paging `gift_card.delivery_failed` event on
**every** failed delivery attempt, not just the terminal one. The attempt budget is eight, so a
single flaky provider window pages an operator up to eight times for one gift card that is
still going to be retried automatically — and the eighth envelope, the only one that actually
needs a human, looks identical to the seven that did not.

Purpose: split the signal. Retries warn, terminal failures page. Nothing about the retry
schedule, the status transitions, or the attempt budget changes — this plan only changes which
event name each already-decided outcome is recorded under.

Output: one new warning-severity event, three call sites that choose correctly between it and
the critical event, and tests that prove the split by which console channel receives the
envelope.
</objective>
