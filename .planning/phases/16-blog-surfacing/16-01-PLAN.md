<objective>
Build the shared data layer every other Phase 16 plan consumes: the five `content.*` admin settings with a
never-throwing, fully-defaulted server-side resolver; the pure excerpt resolver BLOG-03 specifies; and the
opt-in post-body column that gives the excerpt resolver something to fall back to.

Purpose: 16-02 (header nav), 16-03 (home block) and 16-04 (admin tab) all read `content.*`. Proving that one
path end-to-end first — schema default row, database read, per-key fallback, typed result — means an
architectural mistake in the settings path costs one commit instead of four.

Output: `lib/content/settings.ts`, `lib/blog/excerpt.ts`, additive edits to `lib/db/schema/settings.ts`,
`lib/observability/telemetry.ts`, `lib/blog/values.ts` and `lib/models/blog.ts`, plus three test files.

    - An explicit non-empty excerpt is returned verbatim, with no stripping, trimming-to-cap, or ellipsis, even when it is longer than the cap and even when a body is also supplied.
    - An excerpt that is `null`, an empty string, or whitespace only is treated as absent and the body fallback runs.
    - The body fallback strips tags, decodes the five common entities (`&nbsp;`, `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&#39;`), collapses all whitespace runs to single spaces, and trims.
    - Fallback text at or under the cap is returned whole, with no ellipsis.
    - Fallback text over the cap is cut at the last space at or before the cap and gets a single trailing `…`; the returned string never exceeds `maxLength + 1` characters.
    - A single unbroken word longer than the cap is hard-cut at the cap and gets the ellipsis (there is no word boundary to find).
    - No excerpt and no body (absent, `null`, empty, or tags only) returns an empty string — the caller decides whether to render an excerpt line at all.
    - `&amp;lt;` decodes exactly once, to `&lt;`, never twice to `<` (no double-decoding).

  <action>
Create `lib/blog/excerpt.ts` as a pure module. Import nothing from `@/lib/db`, `@/lib/models`, or any React
module — the only thing it may reference is its own logic.

Export `resolveBlogExcerpt(post: { excerpt: string | null; html?: string | null }, maxLength = 160): string`.
The parameter's body member is optional and nullable rather than a required string as D-01 sketched it: the
list read this phase uses returns summary rows, and until a caller opts in (Task 3) those rows carry no body
at all. Making it optional lets the one call site that needs the fallback pass a body while every other
caller keeps working on rows that have none; an absent body is a normal input, not an error.

Logic, in order:
  1. If `post.excerpt` is a string with non-whitespace content, return it exactly as stored. Do not trim it,
     do not cap it, do not append anything — an editor's explicit excerpt is authoritative (D-01, BLOG-03).
  2. Otherwise take `post.html ?? ""`, replace every tag with a single space using the same regex
     `calculateBlogReadingTime` already uses in `lib/blog/values.ts`, then decode the five common named
     entities plus the numeric apostrophe in one pass over the string so that no output of one replacement
     is re-scanned by another. Use a single `String.prototype.replace` with one alternation pattern and a
     lookup object for the replacement, rather than chained sequential replaces — chaining decodes
     `&amp;lt;` twice and turns it into `<`.
  3. Collapse every whitespace run to one space and trim. If the result is empty, return the empty string.
  4. If the result's length is at most `maxLength`, return it.
  5. Otherwise take the first `maxLength` characters, find the last space in that slice, cut there when one
     exists (dropping the trailing space), hard-cut at `maxLength` when none does, and append the single
     ellipsis character.

Write `tests/unit/lib/blog/excerpt.test.ts` covering every bullet in this task's `<behavior>` block, one
case each, plain Vitest `describe`/`it` with no mocks. Include an explicit assertion that the over-cap
return value's `.length` is at most `maxLength + 1`, and one case that passes a custom `maxLength` to prove
the parameter is honoured rather than the default being hardcoded.

Follow the repository's test-first habit for new behaviour: commit the failing test first, then the
implementation.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| D1 `admin_settings` -> server resolver | Stored `content.*` values are attacker-influenceable only through the admin-gated write path, but a tampered or corrupted row must not reach the storefront unvalidated |
| D1 `blog_posts.html` -> derived excerpt text | Author-supplied markup crosses into a string this phase will later render |
| `getPublishedBlogPosts` column set -> every existing caller | Widening a shared read can silently widen a public payload |
