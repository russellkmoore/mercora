<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (admin session) -> `POST /api/admin/settings` | The only write path for `content.*`; it is shared with every other settings category |
| Browser (anonymous) -> `/admin/settings` | An unauthenticated visitor must reach neither the tab nor the values behind it |
| Admin form bounds -> server resolver bounds | Two independent validations that must agree, or an admin saves values the storefront ignores |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-31 | Elevation of Privilege | `content.*` write path | high | mitigate | No new route is added. `POST /api/admin/settings` already calls `checkAdminPermissions` before reading the body or resolving a database handle, and the category has no allowlist to extend. Pinned by the permission-failure case in `tests/unit/app/api/admin-settings-content-category.test.ts`, which asserts the database resolver is never called |
| T-16-32 | Tampering | The honor guard's category carve-out | high | mitigate | The new category must not become a path around the gift-card honor guard. Pinned by the mixed-POST case: a batch containing both a `content.*` key and the guard key is refused whole and writes nothing |
| T-16-33 | Tampering | `handleSave`'s shared `updates` array | medium | mitigate | Every category's keys ride in one batch, so dropping an entry silently clears that setting on the next save. The source test asserts the per-category entry counts for every pre-existing category, not only for content |
| T-16-34 | Input Validation | Admin form bounds diverging from server bounds | medium | mitigate | The form's count bounds and placement options are imported from the same module the server resolver uses; a literal-count grep returning 0 pins that no second copy exists. Even if they diverged, 16-01's unconditional clamp is the authority (T-16-01) |
| T-16-35 | Elevation of Privilege | The admin settings page itself | high | transfer | Already mitigated outside this phase: the Phase 14 middleware sign-in redirect for `/admin` plus `requireAdminSession()` in every async admin page. This plan adds a tab inside that existing boundary and creates no new entry point |
| T-16-36 | Information Disclosure | `content.*` values seeded into the database on first admin GET | low | accept | The five values are a nav label, a heading, a flag, a count and a position. No balance, no personal data, no secret. The category needs no guard clause of its own |

No package-manager install occurs in this plan, so the supply-chain gate does not apply.
