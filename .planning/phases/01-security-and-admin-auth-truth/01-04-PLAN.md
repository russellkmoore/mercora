This plan changes no files in the repository. Its output is a control-plane change and a written
record.

**The value must never appear anywhere.** Generate and upload in a single pipeline so the new
secret exists only in memory between two processes:

```
openssl rand -hex 32 | npx wrangler secret put ADMIN_VECTORIZE_TOKEN
```

Do not assign it to a variable. Do not `tee` it. Do not add it to `.dev.vars` — local development
keeps its own separate value, and `.env.local` is out of scope. Because the value is generated
inside the pipe, no shell history entry contains it. Russell accepted the executor performing this
rotation on exactly that basis; breaking the pipe breaks the consent.

**The old value used by the probes is** `voltique-admin`. It appears in this plan and will appear
in the summary because it is the probe payload and the evidence. It is dead once Task 2 completes.
The SEC-01 acceptance search in plan `01-03` deliberately excludes `.planning/` for this reason.

**Route facts verified during planning, which contradict the documentation:**
`GET /api/admin/vectorize` returns HTTP 405 unconditionally with no authentication check — only
`POST` is authenticated there, and a `POST` that authenticates successfully clears and rebuilds the
entire vector index, a one-to-three-minute destructive operation. `GET /api/admin/knowledge` is
authenticated and read-only. Task 3 therefore probes the read-only endpoint first and only probes
the mutating one after the old value has already been proven rejected. Do not reorder those two.

**On the missing decision checkpoint.** Task 2 carries a one-way reversibility rating with no
preceding `checkpoint:decision`, and `verify.plan-structure` warns about that. The omission is
deliberate: Russell made this exact call on 2026-09-01 in `01-CONTEXT.md` ("The executor performs
the rotation directly"), so the door is already walked through. Inserting a checkpoint would re-ask
a question that has been answered. The rating stays for the record. Do not add a checkpoint.

Project commands run under Node 24 via mise; prefix with `mise exec --` only if plain commands fail.
