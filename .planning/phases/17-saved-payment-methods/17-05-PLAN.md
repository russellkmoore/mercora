    - `app/api/account/payment-methods/route.ts` (created by 17-04) — the `SavedPaymentMethod` type to import and the exact GET response shape
    - `docs/theming.md` — the token-class contract the storefront renders through; no hardcoded palette is allowed in this file
  </read_first>
  <action>
    Create `components/account/PaymentMethodList.tsx`, a `"use client"` component modelled
    directly on `AddressManager` (D-10). It takes no props and fetches its own data: on mount,
    `GET /api/account/payment-methods` with `credentials: "same-origin"`, into
    `useState<SavedPaymentMethod[]>([])` plus `loading`, `busy` and `message` state. Self-fetching
    rather than receiving a server-rendered `initial` prop is a deliberate choice recorded here:
    it keeps the Stripe list call in exactly one place (the route plan 17-04 already tested), and
    keeps a network-bound third-party call off the page's server render path.

    Render three states. Loading: a short "Loading your saved cards…" line. Empty: an explanatory
    line saying no cards are saved yet and that choosing to save a card at checkout will add one
    here — an empty state, not an error, matching the route's empty-list response (D-08).
    Populated: one `article` per card using the same row markup AddressManager uses, showing the
    brand with its first letter capitalised, the last four digits, and the expiry as a
    zero-padded two-digit month and four-digit year. No card-brand icon and no image (D-08 scopes
    the projection to plain text). Exactly one action per row, a "Remove" button; there is no
    Edit button and no add-a-card form section, because cards are only ever added at checkout
    (D-10).

    `remove(id)` first asks `window.confirm` with a short question naming the brand and last four,
    per the Claude's-discretion note in 17-CONTEXT.md — a native confirm, not a new Dialog
    component. On confirm it sets `busy`, calls
    `DELETE /api/account/payment-methods/${encodeURIComponent(id)}` with
    `credentials: "same-origin"`, throws the parsed body's `error` when the response is not ok,
    filters the row out of local state on success, and surfaces either a success line or the
    error text in the `role="status"` paragraph, clearing `busy` in a `finally`. Disable every
    Remove button while `busy` is true, exactly as AddressManager disables its buttons.

    Every colour, border and surface comes from the token classes AddressManager already uses —
    `text-foreground`, `text-muted-foreground`, `text-danger`, `border-border`,
    `bg-surface-elevated`. Do not introduce a literal hex value, an `rgb(` value or a raw Tailwind
    palette class; `npm run scan:tokens` must stay at 0 violations.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous visitor → `/account/payment-methods` | A server-rendered page segment that must never stream to an unauthenticated visitor |
| client component → account API | Every read and every removal goes through the routes plan 17-04 already guards |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-24 | Information Disclosure | `app/account/payment-methods/page.tsx` | high | mitigate | The page performs its own `await auth()` and `redirect()` rather than relying only on the parent layout — the Phase 14 finding was that App Router streams page segments, so each account page gates itself |
| T-17-25 | Elevation of Privilege | removal from the browser | critical | mitigate | The client sends only a payment-method id; the ownership decision is made server-side in plan 17-04's route and cannot be influenced from here (D-09) |
| T-17-26 | Information Disclosure | rendered card data | high | mitigate | The component renders only the five projected fields the route returns; it never has a card number, a Stripe customer id or a fingerprint to leak (D-08) |
| T-17-27 | Tampering | CSRF on removal | high | mitigate | `credentials: "same-origin"` on the fetch, paired with the route's own `hasSameOrigin` check |
| T-17-28 | Information Disclosure | guests and saved-method UI | high | mitigate | The route and page are both behind the Clerk gate and the navigation entry only renders inside the account layout, so a guest never sees any saved-method surface (D-07, PAY-02) |
| T-17-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed by this plan; all three Stripe packages are already installed and audited OK in 17-RESEARCH.md's Package Legitimacy Audit |
</threat_model>
