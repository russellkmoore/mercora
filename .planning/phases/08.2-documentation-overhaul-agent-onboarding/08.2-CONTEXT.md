<decisions>
## Implementation Decisions

### README (DOCS-04)
- **D-01:** `README.md` is rewritten, not patched. Framing: Mercora/Voltique is a themeable reference storefront on Cloudflare (Next.js, D1, R2, Workers AI, Stripe, Clerk) that renders any catalogue; the outdoor-gear demo data is sample content, and `volt-dark` is one of seven presets. Russell's words: the current README is "very outdoor gear specific".
- **D-02:** Structure: one-paragraph what-it-is; a quick start (clone, `mise`, `npm install`, `.dev.vars`, `npm run dev`); a "Themes and layouts" showcase with the seven presets and three layout switches (reuse existing captures from `.screenshots/` or the phase records; commit a small set of optimised PNGs under `docs/images/`); architecture at a glance (one diagram or a short list); a docs index that links only living documents; contributing/gates; licence. Keep it under ~250 lines.

### docs/ inventory (DOCS-04)
- **D-03:** Every file under `docs/` is classified keep / merge / retire in `08.2-DOCS-INVENTORY.md` with a one-line reason each, decided by research against the code and the v1/v2 milestone records. Known candidates from a first look: `admin-dashboard-specification.md`, `mobile-*.md` (four files), `o07-gift-cards-plan.md`, `shopify-migration.md`, `ROADMAP.md` (docs copy), `migration-reservations.md` — verify each before deciding; historical design docs already carry a "Status: Historical" banner from v1 Phase 4 and may be retired or moved to `docs/archive/`.
- **D-04:** Merges are executed, not proposed: e.g. deployment + runtime configuration + database migrations may become one "Setup and deploy" doc if research finds they overlap; `docs/CLAUDE.md` stays the AI-assistant context file but is trimmed of anything now in `AGENTS.md`. Any removed file that is linked from README, other docs, or code comments gets its links updated; a short `docs/CHANGELOG-docs.md` entry records what moved where.
- **D-05:** Style contract (applies to every remaining doc, checked by a lint-ish grep pass): second person, direct ("Run…", "Set…"), sentences under ~25 words, one idea per section, commands and file paths in code formatting, no duplicated content across files (a topic lives in one doc and others link to it), consistent header: `# Title`, one-line purpose, `**Status:**` line where relevant. Russell's words: "not overly verbose, direct language, and cover everything the developer needs to know."
- **D-06:** Claim check: every command, path, env var and script name in the remaining docs is verified against the code (Phase 8's grep/`test -f` method), and `docs/theming.md` keeps its verbatim validator strings.

### AGENTS.md (DOCS-05)
- **D-07:** `AGENTS.md` at the repo root (cross-tool convention). Sections: what this repo is; prerequisites (Node 24 via mise, npm, wrangler login, Cloudflare account, Stripe test account, Clerk app); ordered setup steps with exact commands (clone → `mise install` → `npm install` → create `.dev.vars` from the documented variable list → `npm run dev` → seed → gates → deploy); the gates to run before any commit (`lint`, `typecheck`, `scan:tokens`, `build-themes --check`, `npm test`, `build`); the rules (expand-only migrations, no secrets in `wrangler.jsonc`, token classes only in storefront, admin excluded, Node 24); files the assistant must not edit (generated theme files, migrations already applied, `.planning/`); where each topic is documented (links). Written so a user can say "read AGENTS.md and help me set everything up" and the assistant has every fact it needs.
- **D-08:** `CLAUDE.md` (project root, if present) and `docs/CLAUDE.md` point at `AGENTS.md` for setup; project-specific AI context that is not setup stays in `docs/CLAUDE.md`. README links `AGENTS.md` as "Setting up with an AI assistant".

### Claude's Discretion
- Final keep/merge/retire verdicts (after research), README diagram form, screenshot selection, whether `docs/archive/` or deletion is used for retired historical docs (prefer deletion with a changelog note; git history keeps them).
