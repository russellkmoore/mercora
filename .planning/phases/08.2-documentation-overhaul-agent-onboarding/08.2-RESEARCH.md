## Summary

The repo has 28 files under `docs/`, a root `README.md`, a root `CLAUDE.md`, `docs/CLAUDE.md`, and a root `AGENTS.md` — but the last is currently just the Next.js auto-generated stub (untracked in git), not a real onboarding doc. Four of the 28 docs are locked ADRs referenced by `gsd-ingest-manifest.yaml` (`checkout-trust-boundary.md`, `webhooks-refunds-inventory.md`, `database-migrations.md`, `subscriptions.md`) — these must not be merged away or renamed, only linked to. Four docs already carry a `Status: Historical` banner from v1 Phase 4 and are safe to retire outright. Three more docs are stale-but-unbannered: `docs/ROADMAP.md` (last updated 2025-09-25, contradicts the live `.planning/PROJECT.md`), `docs/o07-gift-cards-plan.md` (a completion/PR-handoff record for a feature that has since shipped), and `docs/migration-reservations.md` (its own numbering ledger is contradicted by migration `0023`, which the code shows was already taken by unrelated work). `docs/api-architecture.md` documents roughly 9 endpoints against 88 real `route.ts` files today, and both it and `docs/architecture.md` end in an identical, decorative, code-unverified "security layers" Mermaid diagram (WAF, bot management, CSRF — none of which exist as literal middleware in this codebase) — a clear duplicated-content violation. `docs/CLAUDE.md` (655 lines) is the single largest source of staleness and duplication: it lists a stale git branch, a hardcoded example D1 database ID, an incomplete CI gate list (missing the theme-check and three test steps CI actually runs), and repeats content that belongs in `AGENTS.md`, `docs/theming.md`, and the four ADRs.

The README rewrite has everything it needs already in the code: `lib/store-config.ts` gives the neutral demo copy ("Mercora... Commerce on the edge"), the 7 theme CSS files carry a structured `@theme label: ... | industry: ... | synopsis: ...` header comment that is the literal source for the preset showcase, `lib/layout/variants.ts` is the single source of truth for the three layout switches and their enum values, and `.screenshots/phase-08-a-<theme>/home__1280__resting.png` has all seven presets already captured at the default layout combination (plus combinations B and C for category/home/product routes, useful for the layout-switch showcase). `AGENTS.md` has a real hazard: Next.js's `next dev` auto-writes a managed `<!-- BEGIN:nextjs-agent-rules -->` block into `AGENTS.md` (verified by reading `node_modules/next/dist/server/lib/generate-agent-files.js` this session) and re-appends it if absent — the plan must keep that block (anywhere in the file) or every future `next dev` run will dirty the working tree.

**Primary recommendation:** Execute the docs consolidation as heavy trims + verified rewrites of existing files (not a single grand merge), preserve the four locked-ADR files and `gsd-ingest-manifest.yaml` paths untouched, retire the 7 identified stale docs with a `docs/CHANGELOG-docs.md` entry each, and build `AGENTS.md` around the Next.js-managed block rather than around it being absent.

**AGENTS.md (DOCS-05)**
- **D-07:** `AGENTS.md` at the repo root (cross-tool convention). ## Common Pitfalls

### Pitfall 1: Deleting or renaming a locked-ADR path
**What goes wrong:** merging `docs/database-migrations.md` into a "Setup and deploy" doc (as D-04's own example phrasing suggests) breaks `gsd-ingest-manifest.yaml`'s `locked: true` entry and any code/doc that links to that exact path.
**Why it happens:** the CONTEXT.md example merge groups ("deployment + runtime configuration + database migrations") reads as an invitation to combine all three into one file.
**How to avoid:** keep all four ADR file paths (`checkout-trust-boundary.md`, `webhooks-refunds-inventory.md`, `database-migrations.md`, `subscriptions.md`) untouched; the "Setup and deploy" merge should link to `database-migrations.md`, not absorb it.
**Warning signs:** any diff that deletes or renames a file matching one of the 4 `locked: true` manifest entries.

### Pitfall 2: Forgetting `gsd-ingest-manifest.yaml`
**What goes wrong:** `/gsd-ingest-docs` (or any future re-run of it) reads a manifest entry pointing at a file this phase deleted.
**Why it happens:** the manifest lives at repo root, not in `docs/`, and wasn't named in CONTEXT.md's required reading.
**How to avoid:** for every retired/merged doc, remove or repoint its `gsd-ingest-manifest.yaml` entry in the same commit.
**Warning signs:** `grep -c "path: docs/" gsd-ingest-manifest.yaml` count should match the final surviving `docs/*.md` count (19, per this inventory) plus `docs/README.md`/`docs/CLAUDE.md`.

### Pitfall 3: AGENTS.md fights `next dev`
**What goes wrong:** every local `next dev` run re-appends the Next.js agent-rules block if it's missing, producing a permanent uncommitted diff that looks like a bug.
**Why it happens:** `next dev` unconditionally checks for the marker pair and appends if absent (verified in source, see AGENTS.md Content Inventory above).
**How to avoid:** include the current block content as the final section of the rewritten `AGENTS.md`, or run `next dev` once after writing and commit the result.
**Warning signs:** `git status` shows `AGENTS.md` modified immediately after a clean commit, with no manual edit.

### Pitfall 4: README screenshots reference the git-ignored `.screenshots/` path
**What goes wrong:** README renders locally (the file exists on the machine that wrote it) but breaks for every other clone/CI/GitHub rendering, since `.screenshots/` is git-ignored.
**Why it happens:** the phase records (`08-QA-MATRIX.md`, `06.1-SCREENSHOTS.md`) all reference `.screenshots/` paths as their evidence trail, which is the natural place to look for existing captures.
**How to avoid:** copy the specific PNGs needed into a new, committed `docs/images/` directory before referencing them from `README.md`; do not add an exception to `.gitignore` for the whole `.screenshots/` tree (it also holds routes with fabricated-but-realistic customer data per `08-QA-MATRIX.md`'s own scope note).
**Warning signs:** `git ls-files docs/images/` empty while `README.md` references `docs/images/*.png`.

### Pitfall 5: Retiring a doc still referenced by code comments
**What goes wrong:** a retired doc's path remains as a dead reference inside a source comment (e.g. `docs/CLAUDE.md` line 379 references `lib/auth/admin-middleware.ts:27` — the reverse direction also exists: code comments may point at `docs/*.md`).
**Why it happens:** D-04 explicitly calls this out, but it's easy to check only README/docs cross-links and skip a repo-wide grep.
**How to avoid:** before finalizing retirements, run `grep -rn "docs/<retired-file>" --include="*.ts" --include="*.tsx" --include="*.mjs" .` (excluding `node_modules`) for each retired path, not just markdown files.
**Warning signs:** any hit outside `docs/`, `README.md`, `AGENTS.md`, `.planning/`.

### Pitfall 6: Treating `docs/CLAUDE.md`'s hardcoded example values as facts
**What goes wrong:** copying `docs/CLAUDE.md`'s "Cloudflare Configuration (wrangler.jsonc)" JSON block (hardcoded `database_id: "c1ea0c17-..."`) into a new doc as if it were the real, current binding.
**Why it happens:** the block looks like real config, but it's a stale illustrative example from an earlier session; the real `wrangler.jsonc` has a different `database_id` (`a27c0044-...`) today.
**How to avoid:** any new doc that shows `wrangler.jsonc` structure should either use placeholder values explicitly labeled as placeholders (as `docs/DEPLOYMENT_SETUP.md` correctly does with `"your-d1-database-id-here"`) or omit the ID field entirely.
**Warning signs:** any doc showing a *specific* database/bucket/index ID as an example rather than a labeled placeholder.
