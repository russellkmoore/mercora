## Issues Encountered

**Sentence-length check vs. code/diagram content:** The plan's sentence-length verify script extracts prose by filtering out lines that start with `|`, `>`, `#`, `` ` ``, `-`, `*`, or a numbered-list digit — it does not understand fenced code blocks or Mermaid diagrams as a unit. Multi-line code snippets and diagram bodies with no internal punctuation were getting glued into single "sentences" of 100+ words, and a markdown line that happens to start with a backtick-wrapped identifier (an artifact of word-wrap) was silently excluded, losing a sentence-ending period further down the same logical sentence. Resolved by: adding a trailing period to a handful of already-present Mermaid `%%` comments and rendered `Note over` text (purely cosmetic, zero effect on rendering), splitting a few long shell/code examples into two labeled blocks, and reflowing a few backtick-adjacent line-wraps so no line started mid-inline-code. No diagram fact, quoted string, or command changed. Final ratio: 0 sentences over 30 words out of 262 counted across the five documents (well under the 5% budget).
