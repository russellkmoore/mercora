<objective>
Close the Phase 6 carry-over with a measurement instead of a guess: `--store-font-display` is fully
wired through the token contract, the Tailwind config and all seven theme files, but no element in
the tree applies the class, so the three display faces plan 06.1-02 just loaded would never render.

There is a known complication this plan must measure rather than assume. Nothing in the tree applies
the `font-sans` class either — `app/globals.css` defines it in the base layer but nothing consumes
it, and `html` carries a literal system font stack. So today's headings render in the system face,
not in `--store-font-sans`. Applying the display class may therefore change headings under
`volt-dark` too, which is precisely the condition CONTEXT made the closure conditional on.

Purpose: the phase must not silently depend on display faces rendering, and must not silently ship a
typography change either. This plan measures, applies the recorded rule, and records the number.

Output: either the display class applied across the storefront's headings with a measured zero
delta, or the change reverted and a Phase 8 hand-off note carrying the measured non-zero delta and
its root cause. Both outcomes are written into `06.1-SCREENSHOTS.md`.
</objective>
