<decisions>
## Implementation Decisions

### Authoring (inherits Phase 6 D-01, D-03, D-05, D-06, D-07)
- **D-01:** Four theme files: `themes/clinical.css`, `themes/retro.css`, `themes/atelier.css`, `themes/market.css`. Each is exactly one `[data-theme="<name>"]` block with all 23 `--store-*` tokens plus the `@theme` header comment (`label`, `industry`, `synopsis` from `docs/voltique-theme-direction.md` sections 3–6). Names are the filename stems.
- **D-02:** Colour values are 6-digit hex converted from the doc's oklch specs; each conversion is noted in the file header as Phase 6 did. Where a doc value fails contrast on its own surface (Phase 6 corrected two), darken/lighten minimally and record the deviation in the file header and in the phase SCREENSHOTS record. The doc's `accent-2` maps to `info` where the doc uses it for status/badges, otherwise it is dropped (D-03).
- **D-03:** The direction doc's extra properties are NOT added (contract frozen one-way, Phase 5 D-01 / Phase 6 D-03). `radius` maps onto the four radius tokens by scaling the doc's single radius the way Phase 6 did for luxe/midnight; `shadow`, `border-width`, `image-aspect`, hover behaviours and decorative backgrounds are recorded as backlog per theme, not implemented.
- **D-04:** Inverse set: mirror the main set's polarity the way luxe (light) and midnight (dark) do — a light preset's drawers/emails/Stripe stay light using its own palette; a dark preset's inverse set is a light complement of its palette. No preset flips the drawers to dark panels in this phase.

### Fonts (inherits Phase 6 D-02)
- **D-05:** Display faces load in `app/layout.tsx` via `next/font/google` with `preload: false`, exposed as CSS variables the theme file references in `--store-font-display`: Orbitron for `retro`, Fraunces for `atelier`, Nunito for `market`. `clinical` uses the Geist stack (doc says Inter or Geist 500). Body font stays Geist for all four (`--store-font-sans`). No `@import`/`@font-face` in theme files (validator forbids them). Verify each face exists in the installed Next font-data manifest before use; if one is missing, fall back to the nearest available Google face and record it.

### QA (inherits Phase 6 D-04)
- **D-06:** Capture all four presets with `npm run screenshot:routes` across the seven-route grid (plus `--include-content` cells), recorded in this phase's `6.1-SCREENSHOTS.md` following 06-SCREENSHOTS.md's format.
- **D-07:** For `clinical`, `atelier`, `market` (light), inspect scrims, shadows and hover states case by case; the Phase 6 scrim fixes (`bg-black/NN` under the scanner sentinel in dialog/alert-dialog/sheet) already apply. Fix only what actually reads wrong, record every judgement including "leave it". Watch specifically for white-on-white hover states (the doc names Clinical as that test) and for `ring`/`border` visibility on near-white surfaces.
- **D-08:** `scan:tokens` stays at 0; `build-themes.mjs --check` passes; the full suite, typecheck, lint and `npm run build` are green at close; `npm run build:worker` still fails on a deliberately broken theme file (spot re-check, restore afterwards).

### Admin
- **D-09:** No admin code changes expected: `ThemePresetGrid` is manifest-driven. Verify the seven cards render (via the existing `renderToStaticMarkup` tests with the regenerated manifest) and that selecting each new preset switches `data-theme` on the next request (dev-bypass header method from 06-04).

### Claude's Discretion
- Exact hex conversions and any contrast nudges; how the doc's `surface-sunken` folds into the contract (Phase 6 mapped the doc's three surfaces onto `surface`/`surface-elevated`, dropping the third); chip/label wording in the header.
