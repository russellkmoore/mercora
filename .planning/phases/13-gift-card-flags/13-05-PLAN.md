<objective>
Build the machinery that measures stranded gift-card money, stores it, and gives the alarm a
name — without a migration and without a per-request query.

D-04 says honoring is ignored while any active balance or open reservation exists. D-05 and D-15
say how we know: one measurement on the five-minute cron tick, written to `admin_settings` under
`gift_cards.honor_guard`, read cheaply by everything else. This plan builds the three pieces —
the query, the record, the event — and plan 13-07 wires them into the cron and into capability
resolution.

Purpose: the measurement half of GCF-02.
Output: an exported balance-sum function, a honor-guard module with a documented staleness rule,
a registered critical telemetry event, and tests at both the D1 and the unit level.
</objective>

    - A card whose status is `disabled` → excluded from the outstanding total.

  <action>
    In `lib/gift-cards/repository.ts`, add one exported async function
    `sumOutstandingGiftCardBalances(database: D1Database, nowSeconds: number)` returning
    `{ outstandingMinor: number; openReservations: number; currency: string | null }`. Place it
    after `availableBalanceExpression` and before `createGiftCardRepository`, so the private
    expression stays private — do not add `export` to `availableBalanceExpression` itself; wrapping
    it keeps SQL construction contained to this one file, matching how the rest of the module is
    structured.

    Build two statements and run them through a single `database.batch([...])` call — one D1 round
    trip, which is what D-05 means by one query:

    Statement A, over `gift_card_accounts account WHERE account.status = 'active'`, selects
    `COALESCE(SUM(<expr>), 0)` as the outstanding total, `COALESCE(SUM(CASE WHEN <expr> > 0 THEN 1
    ELSE 0 END), 0)` as a card count, and `MIN(account.currency_code)` as the currency. Call
    `availableBalanceExpression('account')` to produce `<expr>`; it is interpolated twice, so the
    statement carries two `?` placeholders and `nowSeconds` must be bound twice, in left-to-right
    order. Write the bind call so this is obvious.

    Statement B counts open reservations:
    `SELECT COUNT(*) AS open_reservations FROM gift_card_reservations WHERE released_at IS NULL AND
    committed_at IS NULL AND expires_at > ?`, bound with `nowSeconds` once. This is deliberately
    narrower than the reservation clause inside the balance expression: that clause covers
    reservations that still hold value, while this count is the "someone is mid-checkout right now"
    signal D-05 asks to report separately.

    Coerce every returned value to a number with an explicit fallback to 0, since D1 aggregate
    columns can come back as `null` on an empty table. Return `currency` as `null` when there are
    no active cards; callers pick their own default.

    Add `tests/integration/lib/gift-cards/honor-guard.test.ts` covering the seven cases above.

    - record measured 60s ago with outstanding 1 → true

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-17 | Tampering | `gift_cards.honor_guard` record | high | mitigate | The writer lives in a module whose only caller will be the scheduled handler (plan 13-07); plan 13-08 adds a source-contract test asserting no file under `app/` imports the writer. A forged or edited record could otherwise switch honoring off while balances exist |
| T-13-18 | Denial of Service | `readHonorGuard` fail direction | high | mitigate | Missing, stale, malformed and unreadable all resolve to "balances may exist", so honoring stays on. The only way to turn honoring off is a fresh record that says zero |
| T-13-19 | Denial of Service | per-request balance scan | medium | mitigate | The guard module contains no aggregate SQL, pinned by a grep assertion; the balance query lives only in the repository and is called only by the cron |
| T-13-20 | Repudiation | stranded balances going unnoticed | high | mitigate | The event is registered critical with sample rate 1 in both the producer taxonomy and the tail worker's critical list, so it pages every tick rather than being sampled away |
| T-13-21 | Information Disclosure | the guard record | low | accept | It holds an aggregate money total and a count — no card identity, no code material, no recipient. It is admin-settings data, already admin-gated |
