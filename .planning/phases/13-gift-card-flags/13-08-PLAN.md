<objective>
Make gift cards vanish from the admin and public surfaces when they do not exist, and give the
operator one place to see stranded money when they do.

D-10 and GCF-03 are blunt: both flags off means no nav entry, no admin page, no admin API, no
public balance endpoint. D-05 and GCF-02 want a loud admin banner naming the outstanding balance.
Those two meet in one narrow state, and this plan resolves it deliberately:

- **The sidebar entry and the public balance endpoint follow the configured flags only.** Hiding
  is a presentation decision (D-10's own words). Both off means no entry and a 404, always.
- **The admin gift-card page and its API stay reachable when the honor guard is active**, i.e.
  when honoring is configured off but value is still outstanding. Honoring is a money decision,
  and the operator's window onto money that is still being honored has to stay open — otherwise
  the D-05 banner is unreachable code and GCF-02 has no operator-facing half. There is no nav link
  in that state; the operator arrives from the alarm or by URL.

Purpose: the surface half of GCF-03 and the operator-facing half of GCF-02.
Output: a gated sidebar, a gated-and-bannered admin page, two gated routes, and tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous request → `/api/gift-cards/balance` | Public, rate-limited, bearer-code input |
| Unauthenticated request → `/api/admin/gift-cards` | Must be rejected before any feature state is disclosed |
| Admin session → gift-card operational data | Authenticated but still a boundary for card material |
| Request path → honor-guard record | Read-only by design |
