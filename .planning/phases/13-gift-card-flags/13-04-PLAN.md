<objective>
Stop a gift card being bought when selling is off, and hide the redemption panel when honoring
is off — with the real guard on the server, not in the UI.

Plan 13-03 removed the add-to-cart control from the product page. That is presentation. This plan
adds the decision that actually holds: `priceCheckout` rejects any gift-card line while selling is
off, and `/api/payment-intent` surfaces that as its own error code so the cart can say something
useful (D-09, D-16). It also marks a stale gift-card line in the cart drawer, and removes the
gift-card apply panel from the payment step when honoring is off.

Purpose: the checkout half of GCF-01 and the panel half of GCF-03.
Output: a distinct error class and code, an injectable flag read that keeps 30 existing pricing
tests green, a cart-line mark, a gated panel, and tests for each.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `POST /api/payment-intent` | Fully untrusted; the client can post any cart body it likes |
| Client cart state → server pricing | Cart contents live in browser storage and cannot be trusted |
| Public store config → client components | Feature booleans reach the browser and are advisory there, never authoritative |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-12 | Elevation of Privilege | `POST /api/payment-intent` with a hand-crafted gift-card line while selling is off | high | mitigate | `priceCheckout` throws before pricing or tender; the UI removal in 13-03 is defence in depth only. Pinned by a pricing test and a route test that assert on the server response, not on rendered markup |
| T-13-13 | Spoofing | client-supplied feature booleans | medium | mitigate | The server never reads the flag from the request; `giftCardSalesEnabled` defaults to a server-side `getStoreConfig()` read and is injectable only from test code |
| T-13-14 | Information Disclosure | the new error code | low | accept | `gift_card_sales_disabled` reveals only that a documented public feature flag is off, which the product page already shows |
| T-13-15 | Denial of Service | gating the apply panel on honor | medium | mitigate | The panel is gated on honor, not on sell, so a shopper holding a balance can still redeem while the store has stopped selling — the exact GCF-01 case |
| T-13-16 | Tampering | gift-card backend semantics | high | accept | Out of scope by ADR-CTB-10; reservation, settlement, release and restore are untouched and the existing integration suite proves it |
</threat_model>
