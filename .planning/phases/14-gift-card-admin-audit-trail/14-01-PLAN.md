    - `tests/integration/helpers/d1.ts` — `applyTestMigrations`.
  </read_first>
  <action>
Create `migrations/0024_add_gift_card_events.sql` as a single expand-only migration containing, in order:

1. `CREATE TABLE IF NOT EXISTS gift_card_events` with columns `id TEXT PRIMARY KEY NOT NULL`, `gift_card_id TEXT NOT NULL`, `event_type TEXT NOT NULL` (free vocabulary, no CHECK, matching `order_events`), `actor_type TEXT NOT NULL CHECK (actor_type IN ('admin','service','system'))`, `actor_id TEXT`, `details TEXT CHECK (details IS NULL OR (json_valid(details) AND json_type(details) = 'object'))`, `created_at INTEGER NOT NULL`, and `FOREIGN KEY (gift_card_id) REFERENCES gift_card_accounts(id) ON DELETE RESTRICT`. Per D-01 the timestamp is an integer epoch second, matching every other gift-card table, and the foreign key restricts rather than cascades.
2. `CREATE INDEX IF NOT EXISTS gift_card_events_gift_card_id_created_at_idx ON gift_card_events (gift_card_id, created_at);`
3. `CREATE INDEX IF NOT EXISTS gift_card_events_event_type_created_at_idx ON gift_card_events (event_type, created_at);`
4. `CREATE UNIQUE INDEX IF NOT EXISTS gift_card_events_reissued_once_idx ON gift_card_events (gift_card_id) WHERE event_type = 'reissued';` — this is D-01's once-only reissue guarantee and D-06's enforcement point.
5. `ALTER TABLE gift_card_accounts ADD COLUMN code_suffix TEXT;` per D-02. Add it with no CHECK and no default: SQLite's ADD COLUMN is restricted, and the four-uppercase-character shape is asserted in TypeScript instead (plan 14-03). Rows issued before this migration keep NULL and are never backfilled — D-02 rules a backfill out explicitly.
6. `CREATE INDEX IF NOT EXISTS gift_card_accounts_code_suffix_idx ON gift_card_accounts (code_suffix) WHERE code_suffix IS NOT NULL;` so D-15's suffix search has an index.

Then edit `lib/db/schema/gift-cards.ts`: add `codeSuffix: text("code_suffix")` to the `giftCardAccounts` column map and `index("gift_card_accounts_code_suffix_idx").on(table.codeSuffix)` to its index array; and export a new `giftCardEvents = sqliteTable("gift_card_events", ...)` using the `order-events.ts` idiom with `details: text("details", { mode: "json" })`, `createdAt: integer("created_at").notNull()`, a `giftCardId` reference to `giftCardAccounts.id` with `{ onDelete: "restrict" }`, both non-unique indexes, a `uniqueIndex("gift_card_events_reissued_once_idx").on(table.giftCardId).where(sql\`${table.eventType} = 'reissued'\`)`, and a `check("gift_card_events_actor_type_check", ...)` matching the migration. Export `type GiftCardEventRow = typeof giftCardEvents.$inferSelect;`. Follow this file's existing array-style second argument, not `order-events.ts`'s object style.

Finally add one `it(...)` case to `tests/integration/gift-cards-migration.test.ts`, in the style of the existing `0022` case: find the index of `0024_add_gift_card_events.sql` in `env.TEST_MIGRATIONS`, apply everything before it, insert a baseline gift-card account (64-character lowercase hex `code_hash`, `code_hash_version` 1, `currency_code` `USD`, `status` `active`, distinct `issuance_entry_id`/`issuance_business_key`, integer `created_at`) plus its `issuance` ledger entry, snapshot both rows as JSON, apply `0024` alone, and assert: the snapshot is unchanged; `SELECT count(*) FROM gift_card_events` is 0; `code_suffix` on the baseline account is NULL; two `reissued` inserts for the same `gift_card_id` leave the second rejected while two `note` inserts both succeed; an `actor_type` outside the three-value vocabulary is rejected; a `details` value that is a JSON array rather than an object is rejected; and `DELETE FROM gift_card_accounts WHERE id = ?` is rejected while an event references it.
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-01 | Tampering | `migrations/0024_add_gift_card_events.sql` | high | mitigate | Additive statements only (CREATE TABLE / CREATE INDEX / ADD COLUMN); proven by `npm run check:migrations` classifying it expand-only, and by the ordering test asserting a populated 0023 baseline is byte-identical afterwards |
| T-14-02 | Tampering | double reissue of one card | high | mitigate | `gift_card_events_reissued_once_idx` partial UNIQUE index; the ordering test proves the second insert is rejected by the database |
| T-14-03 | Repudiation | `gift_card_events.actor_type` | medium | mitigate | `CHECK (actor_type IN ('admin','service','system'))` so no event can be written without a recognised actor class (D-01) |

| T-14-05 | Information Disclosure | `gift_card_accounts.code_suffix` | low | accept | Four characters of a 28-symbol code (about 20 bits of the code's 140) are already printed by `maskGiftCardCode` in customer email and at checkout; it is display and search material, not bearer material (D-02) |
| T-14-06 | Denial of Service | orphaned event rows blocking account deletion | low | accept | ON DELETE RESTRICT is deliberate — an audited card must not be deletable while its history exists (D-01); nothing in this codebase deletes gift-card accounts |
