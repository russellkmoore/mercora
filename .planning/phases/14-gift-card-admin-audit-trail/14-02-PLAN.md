<objective>
Unblock the reveal setting and give every route in this phase one shared HTTP scaffold.

Two of Phase 13's design choices block Phase 14 as written: the generic settings route
refuses the whole `gift_cards` category (so the new reveal toggle could never be saved),
and there is no shared bounded-JSON/actor helper for admin gift-card routes — the only
copy lives inside the orders ship route. This plan fixes both without touching money code.

Purpose: waves 2-4 depend on these two things existing and on Phase 13's write contracts
still being green afterwards.
Output: a narrowed guard, one new default setting, one new shared module, two test files.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser -> `POST /api/admin/settings` | an authenticated admin supplies an arbitrary settings key and value |
| admin browser -> every gift-card admin route | untrusted JSON body crosses here; `readBoundedJsonBody` is the first thing that touches it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-07 | Tampering | `writesTheHonorGuard` narrowing | high | mitigate | Narrow to the exact key with a trimmed comparison; a regression test asserts the guard key and a padded variant are both still refused with `honor_guard_read_only` |
| T-14-08 | Elevation of Privilege | `gift_cards.code_reveal_enabled` default | high | mitigate | Declared as `JSON.stringify(false)`; a store that never touches it cannot reveal a code. The route in plan 14-07 additionally requires `isSuperAdminActor` |
| T-14-09 | Denial of Service | JSON body size on every new route | medium | mitigate | `readBoundedJsonBody` caps at 4096 bytes, checking the declared `content-length` and the encoded length, so a lying header cannot bypass the cap |
| T-14-10 | Spoofing | same-origin on mutations | high | mitigate | `checkAdminPermissions` already refuses a cookie-authenticated POST/PUT/PATCH/DELETE from a foreign origin; every route in this phase keeps it as its first statement rather than re-implementing the check |
| T-14-11 | Repudiation | actor attribution | medium | mitigate | `actorFrom` is the single builder, and its output type is the same `Actor` union the `gift_card_events.actor_type` CHECK enforces, so an unattributable event cannot be constructed |
</threat_model>
