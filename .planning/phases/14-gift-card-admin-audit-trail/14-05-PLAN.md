<objective>
Teach the one module that is allowed to touch bearer codes three new things: record the
code suffix at issuance, issue a card with no order behind it, and send a delivery email
again.

Everything that decrypts a code, renders the delivery email, or hands the sender a worker
environment stays inside `lib/services/gift-card-fulfillment.ts`. Its `deliveryMessage`,
`emailEnvironmentFrom` and `giftMessageFor` helpers are module-private and stay that way —
a route that imported them would have to re-implement the AAD binding or the env
forwarding, and both have already cost this project a production incident.

Purpose: plans 14-06 and 14-07 call these two exported functions instead of writing any
code-handling logic of their own.
Output: two new exports, one changed call site, integration coverage against real D1.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ciphertext at rest -> decrypted plaintext | resend is a second place a bearer code exists in memory; only this module may cross it |
| admin-supplied `to` address -> outbound email | a fraud-recovery feature that can also be an exfiltration path |
| worker env -> email sender | a partial environment silently loses the EMAIL binding, which has already broken production once |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-25 | Information Disclosure | resend to an attacker-supplied address | high | mitigate | The address is a required part of the audit event plan 14-07 writes before responding (D-08); this function returns a result the route records, and it never writes the typed address onto the delivery row where it would become the permanent destination |
| T-14-26 | Information Disclosure | bearer plaintext in logs or errors | high | mitigate | Both new functions keep the code in the narrowest scope and copy `issueLine`/`deliverOne`'s discipline: never returned, never logged, never attached to an error |
| T-14-27 | Tampering | resend mutating delivery state | medium | mitigate | The function issues no UPDATE at all; an integration case compares a before/after JSON snapshot of the row |
| T-14-28 | Denial of Service | resend swallowed by the sender's dedupe | medium | mitigate | The caller-supplied `idempotencyKey` is required and distinct per event (D-08); an integration case asserts the row's own key is not what reaches the sender |
| T-14-29 | Spoofing | decryption without AAD binding | high | mitigate | `decryptGiftCardDeliveryCode` is called with the AAD taken from the row's own gift-card and delivery ids; no new AES-GCM call site is created |
| T-14-30 | Elevation of Privilege | admin-create used to mint an unbounded balance | high | mitigate | The amount is validated against a named ceiling derived from the product's configured denominations before any write, and the account CHECK on `issued_amount_minor` is the backstop (D-07) |
</threat_model>
