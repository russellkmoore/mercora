Create components/gift-cards/GiftCardRecipientBlock.tsx in a new components/gift-cards/ directory. It carries no client-component directive, no React hook and no event handler — it is props in, JSX out — because plan 10-04 imports it into an async Server Component.

Export a const named GIFT_CARD_MESSAGE_PREVIEW_LENGTH set to 80.

Export a pure function truncateGiftCardMessage taking a string and returning a string. It splits the input into code points with Array.from, returns the input unchanged when that array's length is at most GIFT_CARD_MESSAGE_PREVIEW_LENGTH, and otherwise joins the first GIFT_CARD_MESSAGE_PREVIEW_LENGTH code points and appends a single horizontal-ellipsis character. Counting code points rather than UTF-16 code units is the point of this helper: it is what keeps an emoji at the boundary from being cut in half.

Export an interface GiftCardRecipientBlockProps with a required customization of type GiftCardCustomization imported from @/lib/types/cartitem, an optional tone that is either the string default or the string inverse, and an optional variant that is either the string compact or the string detail. The two props are orthogonal: tone picks the token set for the surface's background, variant picks the density and the message treatment. Enumerated variants rather than per-surface component copies is the architecture this codebase already settled on.

Default-export GiftCardRecipientBlock taking those props with tone defaulting to the default value and variant defaulting to compact. Resolve two class strings from tone: for the inverse tone the To line is text-on-inverse and the other two lines are text-muted-on-inverse; for the default tone they are text-foreground and text-muted-foreground. Resolve the wrapper class from variant: compact wraps the three lines in a div carrying text-xs, detail wraps them in a div carrying text-sm space-y-0.5.

Render the To line first, always: a paragraph with mt-1 and the To class, whose text is the string "To: " followed by the recipient name, a space, and the email wrapped in angle brackets when a recipient name is present, and "To: " followed by the email alone when it is not.

Render the Deliver line second, only when deliveryDate is present: a paragraph with mt-1 and the rest class reading "Deliver: " followed by the date exactly as stored.

Render the message line third and last, only when message is present, and let variant decide its treatment. On the compact variant it is a paragraph with mt-1 and the rest class, carrying a title attribute set to the full untruncated message and text set to truncateGiftCardMessage of that message; it does not preserve newlines, because the title attribute is what carries the whole text on a compact card. On the detail variant it is a paragraph with mt-1, the rest class and whitespace-pre-line, holding the full message with no truncation and no title attribute, because a detail page has room for the whole thing. Only the message line differs between the two variants; the To line and the Deliver line are identical in both.
