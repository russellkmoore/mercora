  <precondition>The production `pages` table holds exactly one row with `slug = 'terms-of-service'` and `status = 'published'` — confirmed read-only during research on 2026-09-09.</precondition>
  <action>
Write `$SCRATCH/12-terms-update.mjs`. It reads the row, builds the new content from what it read, and emits the SQL. It never hand-copies the page's existing text, because a hand-copied literal that drifts by one character would clobber content rather than extend it (T-12-11).

Steps the script performs:

1. Run `mise exec -- npx wrangler d1 execute mercora-db --remote --json --command "SELECT id, slug, status, version, updated_at, published_at, length(content) AS len, content FROM pages WHERE slug='terms-of-service';"` and parse the JSON.
2. Assert exactly one row came back, `status` is `published`, and `slug` is `terms-of-service`. Abort otherwise.
3. Idempotence guard: if the content already contains a `6. Gift Cards` heading, print that the section is already present and exit 0 without generating any SQL. A second run must not append a duplicate section.
4. Locate the closing paragraph `<p>For questions about these terms, please contact us.</p>` — the last paragraph of the page, and the same insertion point the pre-existing `5. Recurring Orders` section used. Abort if it is not found exactly once.
5. Build the new content by inserting this block immediately before that closing paragraph, keeping every preceding section byte-identical:

   `<h2>6. Gift Cards</h2>`
   `<p>Gift cards are delivered to the recipient by email as soon as payment completes. They never expire, cannot be redeemed for cash, and cannot be transferred or resold. Stored value can be used across multiple orders. If you have a question about a gift card, please contact us. Gift card terms version 2026-09-09.</p>`

   Only `h2` and `p` are used, both of which the sanitizer allows, so nothing is stripped when the page renders.
6. Write `$SCRATCH/12-terms-update.sql` containing one statement: `UPDATE pages SET content = '<new content>', version = version + 1, updated_at = CAST(strftime('%s','now') AS INTEGER) WHERE slug = 'terms-of-service' AND status = 'published';`. Escape every single quote in the content by doubling it, programmatically — the existing text contains apostrophes, and getting this wrong by hand is the failure mode a generator exists to prevent. Leave `published_at` untouched: a NULL there already means always-published, so writing it would change nothing and widen the diff.
7. Print the before values — id, version, updated_at, content length — and the new content length. Print the full pre-update content to a scratch file so the SUMMARY can carry it verbatim.

Generate the SQL only. Do not execute it in this task.
  </action>
  <acceptance_criteria>

    - `$SCRATCH/12-terms-update.sql` exists and contains exactly one `UPDATE` statement.
    - `grep -c "WHERE slug = 'terms-of-service' AND status = 'published'" $SCRATCH/12-terms-update.sql` returns 1.
    - `grep -cE '^\s*(DELETE|DROP|ALTER|INSERT)' $SCRATCH/12-terms-update.sql` returns 0.
    - The generated new content length exceeds the old length by the length of the inserted block, and no earlier section is missing from it.
  </acceptance_criteria>
  <verify>
    <automated>mise exec -- node $SCRATCH/12-terms-update.mjs &amp;&amp; grep -cE '^\s*(DELETE|DROP|ALTER|INSERT)' $SCRATCH/12-terms-update.sql</automated>
    <fails_when>The generator exits nonzero (no row, wrong status, missing or duplicated insertion point, or the section already exists) or the destructive-statement count is not 0 — in either case nothing is applied and the row is untouched.</fails_when>

| T-12-13 | Elevation of Privilege | writing CMS content without an admin session | medium | accept | Explicit one-time exception under D-02, scoped to a single row and a single statement, performed under Russell's own Cloudflare credentials on his own store. | T-12-14 | Tampering | injecting HTML the renderer would execute | medium | mitigate | Only `h2` and `p` are written, both on the sanitizer's allow list, and `PageRenderer` re-sanitizes on every render, so even a raw write cannot bypass the policy. |
