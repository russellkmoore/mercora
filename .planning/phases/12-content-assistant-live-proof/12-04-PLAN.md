<objective>
Re-index Volt so it answers gift, present and voucher questions with the gift card, and prove it does.

Per D-01 the re-index runs as a local Node script on 12-01's remote-binding harness, reproducing the algorithm in `app/api/admin/vectorize/route.ts` rather than calling that route. The route needs `ADMIN_VECTORIZE_TOKEN`, a secret this run never reads, and rotating it would break Russell's own copy.

Scope decision, taken under D-01's discretion clause and recorded here because it narrows the run: this plan reproduces only the route's knowledge-article step, not its product step. 12-01 verified read-only that `prod_33` already carries a healthy product vector whose stored text lists the gift, present, voucher and gift certificate vocabulary Phase 9 seeded, so the product side of CONTENT-02 is already satisfied. The route's product step begins by clearing the whole index with `deleteByIds`, the single most destructive operation available here, and it buys this phase nothing. The knowledge step is pure upsert by stable id: it replaces `knowledge-gift-cards` in place and touches no other vector. That is the T-12-16 mitigation, not a shortcut.

Purpose: CONTENT-02.
Output: a refreshed knowledge vector, before-and-after index counts, and three recorded Volt replies.
</objective>

  <action>
Write `$SCRATCH/12-reindex-knowledge.mjs`. It imports the binding opener from `$SCRATCH/12-remote-env.mjs` and reproduces the admin route's knowledge step.

Record the baseline first, per D-03: run `mise exec -- npx wrangler vectorize info voltique-index` and capture `vectorCount` and `dimensions`, then `mise exec -- npx wrangler vectorize get-vectors voltique-index --ids knowledge-gift-cards` and capture that its stored text is still the pre-12-02 article.

Then, for each object under the `knowledge_md/` prefix, in the order the route walks them:

- Skip anything not ending in `.md`, exactly as the route does.
- Derive the slug by stripping the prefix and the extension.
- Fetch the object and read it as text. Skip with a logged error if the text is missing or shorter than ten characters, matching the route's guard.
- Embed the whole raw file text, front matter included, using the embedding model id read from `lib/ai/config.ts`. The route does no YAML parsing, so neither does this (12-RESEARCH.md Pitfall 4).
- Upsert a single vector whose id is the literal prefix `knowledge-` followed by the slug, whose values are the first element of the embedding's data array, and whose metadata carries exactly three fields: the slug, a source of `knowledge`, and the first 1000 characters of the text. Nothing more. The chat route reads only the text and productId fields, so an extra field would be dead weight that diverges from what the admin route writes (12-RESEARCH.md Pitfall 5).

The script contains no index-clear call, no vector-removal call, no product table query, and no write to the product-markdown prefix in R2. Keep all of them out of the source rather than guarding them at run time, so the source grep in the acceptance criteria is a real gate.

Log one line per article with slug, text length and embedding length, print a final count, and exit nonzero if any article fails.

Read back afterwards, per D-03: `wrangler vectorize info voltique-index` for the after-count, and `wrangler vectorize get-vectors voltique-index --ids knowledge-gift-cards` to confirm the stored text is now the rewritten article. Vectorize applies mutations asynchronously, so if the read-back still shows the old text, wait and re-read rather than re-running the upsert.

Record in the SUMMARY the before and after vector counts, the slugs processed, and the first line of the refreshed vector's stored text.
