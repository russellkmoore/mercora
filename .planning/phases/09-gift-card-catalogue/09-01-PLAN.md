## Planner Assumptions

The specless edge probe left CAT-01, CAT-03 and CAT-04 unclassified. Resolved where possible into `must_haves.truths` above; the residue is recorded here rather than dropped.

1. **CAT-01 (unclassified).** "Applied to production D1 with idempotent SQL" is read as: the block is `INSERT OR IGNORE`, and the file handed to `--remote --file` contains only that block. Research Finding 3 verified that pointing `--file` at the whole `data/d1/seed.sql` aborts on the first `categories` insert, so a whole-file production apply is treated as out of contract, not as an alternative.
2. **CAT-02 (unclassified residue).** The four denomination prices are rendered inside a Radix `Select` whose content is portaled and only mounted when the select is opened, so only the default variant's `$25.00` appears in SSR HTML. The four-price claim is therefore proven by the D1 read-back and the serializer test (09-02), not by grepping the initial HTML. A screenshot or human look is not planned; Russell accepts code-level evidence at these gates.
3. **CAT-03 (unclassified).** Workers AI `@cf/leonardo/lucid-origin` returns JPEG bytes even when the file is named `.png` — both sibling images (`field-ration-resupply-31.png`, `campfire-smores-kit-32.png`) are JPEG data at 1024x1536. The image acceptance criterion is therefore dimension-based, not container-based. Recorded here so a later reader does not "fix" the extension.
4. **CAT-04 (unclassified).** "A paid order does not decrement inventory" is proven against the already-shipped skip in `lib/services/inventory-adjustments.ts`, using a gift-card-shaped `OrderItem`. The catalogue seed cannot itself carry `gift_card` customization — that is an order-item field Phase 10 supplies — so this phase proves the catalogue half (`fulfillment_type` `digital`) and the skip half separately.
5. **Standalone `inventory` table rows are deliberately skipped** for the four variants (no `inv_33`). Research Finding 4 verified that no query in `lib/models/mach/products.ts` joins it and no file under `app/` or `components/` imports `lib/models/mach/inventory.ts`. This diverges from the 32 existing products, which all carry one; recorded as a decision, not an omission.
6. **One `pricing` row, not four.** The `pricing` table is product-scoped (`price_31` -> `prod_31`), so four variant prices cannot be represented there. `price_33` carries the default variant's 2500 for shape consistency with the other 32 products; nothing reads it.
