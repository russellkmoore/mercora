# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase has **two distinct UI surfaces** governed by different rules:

1. **Admin Appearance page** (`app/admin/settings/appearance/page.tsx`) — a normal admin UI screen. It uses admin's existing **hardcoded** neutral-800/900/950 palette (D-16, TOKEN contract §Out of Scope: "Admin dashboard theming"). The `## Color` / `## Typography` sections below specify this page.
2. **Two new storefront theme presets** (`luxe`, `midnight`) — not a page, a **token-value contract**. These are CSS custom-property values a `themes/*.css` file sets, consumed by every already-swept storefront component. Specified in `## Preset Token Contracts` below, additive to the template.

### Font loading (D-02)

```tsx
// app/layout.tsx — add alongside the existing Geist imports
import { Cormorant_Garamond } from "next/font/google";

const cormorantGaramond = Cormorant_Garamond({
  variable: "--font-cormorant-garamond",
  subsets: ["latin"],
  weight: ["400", "500"],
  display: "swap",
  preload: false, // D-02: never preload a non-default display face
});

// add cormorantGaramond.variable to the existing body className list,
// alongside geistSans.variable / geistMono.variable — the CSS var is
// then always defined, but the browser only fetches the font file when
// a page actually renders text with font-display under [data-theme="luxe"]
```

No `@import` or `@font-face` may appear inside any `themes/*.css` file (D-02, enforced by the D-06 validator) — Cormorant Garamond is loaded exactly once, in the root layout, for every theme.

### Light-Preset QA Finding (D-04) — flagged for the phase's own QA pass, not resolved here

`bg-surface/NN` opacity-based scrims already exist, **token-driven, not literal `bg-black`**, at:

- `components/ui/dialog.tsx:106` — `bg-surface/80`
- `components/ui/alert-dialog.tsx:39` — `bg-surface/50`
- `components/ui/sheet.tsx:128` — `bg-surface/50`
- `app/category/[slug]/page.tsx:133` — `bg-surface/40` (hero image overlay)

Under `volt-dark` (`surface: #000000`) these already read as a black-alpha scrim — matching D-04's description of today's look. Under `luxe` (`surface: #f8f5ef`, ivory) the *same class* renders as a **light ivory-tinted scrim**, which will not visually recede the backdrop behind a modal/sheet/drawer the way a scrim is supposed to. This is exactly the class of defect THEME-04's light-preset QA criterion exists to catch ("the light preset's shadows and overlays read correctly rather than as dark-tuned leftovers").

D-04 explicitly reserves the fix to the QA pass, case-by-case, and forbids introducing "a blanket surface-relative overlay class." Two directions the QA pass can take (not decided here):
1. Judge the light ivory scrim acceptable as-is (D-04's "polarity-neutral" framing may cover this) if it still visually separates the modal from the page.
2. If it reads wrong, the fix needs a token-independent dark scrim — which cannot be a literal `bg-black/NN` class (the scanner's palette list explicitly includes `black`/`white`, `scripts/scan-hardcoded-colors.mjs:75`) without a scanner exception, so the resolution likely needs its own small design decision at execution time.

Recorded here as a known, concrete pre-identified item for the D-04 QA checklist — not something the researcher is resolving on the planner's behalf.

## Admin Appearance Page Layout (THEME-03) — additive to the template

### Route & navigation (D-13)

New file: `app/admin/settings/appearance/page.tsx`. The existing settings hub (`app/admin/settings/page.tsx`) has **no existing routed sub-pages today** — its seven sections (`system`, `store`, `shipping`, `refunds`, `promotions`, `social`, `admins`) are all client-state tabs rendered inline, not routes. Appearance is architecturally different (its own route), so add an eighth entry to the `tabs` array whose click handler is a real navigation (`next/link` to `/admin/settings/appearance`) rather than `setActiveTab`, styled identically to the other seven tab buttons (`Palette` icon from lucide-react, label "Appearance", description "Theme & look"). The visited/active styling (`bg-orange-600 text-white` when current) should reflect the current route via `usePathname()`, not the `activeTab` state.

### Card anatomy (D-14), in this fixed order

1. **Colour chips** — exactly 5, in this order: `primary`, `surface`, `surface-elevated`, `foreground`, `surface-inverse`. Rendered as small squares/circles (~24px) with inline `style={{ backgroundColor: manifest[theme].tokens.primary }}` etc. — this is the one place raw hex belongs in admin markup (D-16).
2. **Inline mini-mock** — a small rectangle (~96–120px tall, `radius-md` from that theme's own tokens) with `background-color: surfaceElevated`, containing one line simulating a heading (`color: foreground`, ~14px) and one small pill/button simulating a CTA (`background-color: primary`, `color: onPrimary`, `border-radius: radiusSm`). All values read from the manifest via inline `style`, never Tailwind classes — the point is to preview a theme that is not the one currently active on the page rendering the preview.
3. **Label** — the theme's `label` (h3, 18px semibold, admin's own `text-white`).
4. **Industry line** — 12px, admin's own `text-gray-400`, omitted entirely if absent (not rendered as an empty line).
5. **Synopsis** — 14px, admin's own `text-gray-400`, `line-clamp-3`, omitted if absent.
6. **Active badge** — top-right corner or inline after the label, only on the currently-saved theme (not the pending selection — see `## UI Considerations`).

### Selection & save model (D-15)

Click anywhere on a card (outside interactive sub-elements, if any) to mark it the **pending selection** — visually distinct from Active via a `ring-2 ring-orange-500` outline (admin's existing accent, matches the Save button color) plus a subtle border-color change, not a re-colored background (a re-colored card background would be confused with the theme preview itself). A single **Save Changes** button (bottom or top of the grid, matching the hub's placement pattern) is enabled only when the pending selection differs from the currently-saved theme; on success, the Active badge moves to the new card and a toast confirms (copy in `## Copywriting Contract`).
